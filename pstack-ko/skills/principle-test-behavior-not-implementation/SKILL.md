# Test Behavior, Not Implementation (구현이 아닌 동작을 테스트)

테스트는 코드의 사용자가 인터페이스를 통해 관찰할 수 있는 것, 즉 반환 값, 에러, 다시 읽을 수 있는 상태, 외부 시스템에 미치는 효과에 대한 주장입니다. 프라이빗 헬퍼, 내부 호출 순서, 중간 데이터는 구현입니다.

각 테스트를 두 가지 가상의 편집에 비추어 판단하세요:

- **동작을 깨뜨리세요**(잘못된 값, 건너뛰거나 두 번 일어나는 효과). 그래도 테스트가 통과한다면 아무것도 증명하지 못합니다. 흔한 원인은 느슨한 단언, 테스트 대상 코드가 계산한 기대 값, 테스트가 직접 만든 데이터에 대한 단언입니다.
- **내부를 바꾸되** 관찰 가능한 결과는 모두 유지하세요. 테스트가 실패한다면 구현에 묶여 있는 것입니다.

첫 번째 편집을 잡아내고 두 번째 편집에서 살아남는 테스트는 유지하세요. 나머지는 다시 작성하거나 삭제하세요. 구체적인 입력으로 공개 인터페이스를 통해 코드를 구동하고, 기대 값은 요구사항에서 도출하세요. 외부 서비스가 받는 것은 동작입니다. 내부 헬퍼 호출은 아닙니다. "이것은 절대 일어나지 않는다"는 테스트에는 실제로 일어나는 케이스를 짝지으세요. 메시지가 아니라 호출자가 분기하는 에러 타입을 단언하세요.
