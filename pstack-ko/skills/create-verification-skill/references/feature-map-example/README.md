# Notes 검증 맵

이 디렉터리는 Notes의 사용자 대면 동작을 검증하는 유지되는 소스입니다. 앱을 구동하기 전에 인덱스를 읽고, 그런 다음 일치하는 기능 파일을 레시피로 사용하세요.

## 기준 전제 조건

- 일회용 데이터 디렉터리로 `http://127.0.0.1:4173`에서 Notes를 시작하세요.
- 동시 실행이 상태를 공유하지 않도록 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`를 설정하세요.
- 제목이 `Quarterly plan`과 `Grocery list`인 노트를 시드하세요.
- `control-notes`와 `notes` CLI를 `PATH`에 두세요.
- `control-notes doctor`를 실행하고, 예상 URL, 데이터 디렉터리, 빌드 리비전을 요구하세요.
- 이 검증 실행이 시작하지 않은 인스턴스는 절대 구동하지 마세요.

## 구동 관례

- 전제 조건이 달리 말하지 않는 한, 모든 레시피를 기준 상태에서 시작하세요.
- CSS 선택자나 DOM 위치보다 ARIA 역할과 접근 가능한 이름을 선호하세요.
- 모든 명령을 문자 그대로 취급하세요. 따옴표 친 이름과 플래그는 바꾸지 마세요.
- 브라우저 동작은 `control-notes browser`로 실행하세요.
- 터미널 동작은 `control-notes cli -- <command>`로 실행하세요.
- 변경 뒤에 시드 데이터를 복원하세요. 정리 중에 증명 아티팩트를 제거하지 마세요.

## 증명과 건너뛰기 보고

- 최종 화면만이 아니라 사용자 동작과 그 결과 상태를 캡처하세요.
- UI 증명에는 ARIA 스냅샷과, 앱 정체가 보이는 스크린샷이 포함됩니다.
- CLI 증명에는 명령, stdout, stderr, 종료 코드가 포함됩니다.
- 변경 증명에는 저장된 값을 읽기 전용으로 다시 본 것이 포함됩니다.
- 모든 아티팩트와 함께, 사용한 기능 ID와 진입점을 기록하세요.
- 도달할 수 없는 경로는 시도한 명령과 충족되지 않은 전제 조건으로 보고하세요.
- 건너뛴 진입점을, 다른 경로로 검증된 것처럼 보고하지 마세요.

## 기능 항목 계약

각 기능 파일은 H1 제목과, 사용자에게 보이는 동작을 설명하는 한 문단으로 시작합니다. 그런 다음 이 순서로 H2 섹션을 정확히 네 개 사용합니다.

1. `하위 기능`은 각 동작에 한 줄씩, 짧은 ID를 나열합니다.
2. `도달하는 방법 (사용자 관점)`은 사용자의 진입점을 모두 나열합니다.
3. `<하니스>로 구동하기`는 `전제 조건:`으로 시작하고, 각 사용자 동작을 정확한 명령과 관찰 가능한 결과에 짝짓는 레이블 불릿을 사용합니다.
4. `주의점`은 검증 실행을 낭비하거나 무효로 만들 수 있는 함정을 나열합니다.

구현 세부 사항은 맵에 넣지 마세요. 사용자 경로, 안정적인 핸들, 필요한 상태, 명령, 관찰 가능한 증명만 이름 붙이세요.

## 기능

- [노트 만들기](./create-note.md)는 브라우저와 CLI에서의 생성, 취소, 지속, 정리를 다룹니다.
- [노트 검색](./search.md)은 툴바, 키보드, CLI 검색과 일치, 비어 있음, 지우기 상태를 다룹니다.
