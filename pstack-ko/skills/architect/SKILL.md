# Architect

코드를 작성하기 전에 변경이 닿는 모든 시스템을 추적한 다음, 그에 대한 서로 다른 두 가지 형태(타입, 시그니처, 모듈 경계)를 스케치하고, 각 상태 조각의 소유자가 하나이고, 각 작업을 수행하는 방법이 하나이며, 호출자가 알아야 할 것이 가장 적은 쪽을 고르세요. 해결책이 반복된다면 패치하는 대신 재설계하세요.

크거나 논쟁의 여지가 있는 설계라면 혼자 스케치하는 대신 **arena** 스킬을 실행하세요.
