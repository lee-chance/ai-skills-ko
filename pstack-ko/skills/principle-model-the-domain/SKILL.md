# Model the Domain (도메인 모델링)

조건문에 흩어뜨리는 대신 데이터 구조에 도메인을 인코딩하세요. 올바른 구조는 불법 상태를 표현 불가능하게 만들고 분기를 삭제합니다.

흩어진 불리언이나 단계 체크 대신 상태 머신을, 느슨한 매개변수 대신 타입이 있는 모델을, 여러 파일에 퍼진 분기 대신 맵, 레지스트리 또는 판별된 유니온을, 임시 상태 변경 대신 reducer를, 액세스 패턴이 요구하는 곳에는 인덱스, 큐 또는 정규화된 컬렉션을 사용하세요.

강제하지 마세요. 형태가 명확하고, 로컬이고, 성장할 가능성이 낮다면 지루한 코드를 유지하고, 분기나 불법 상태를 제거하지 않으면서 간접 참조만 추가하는 추상화는 경계하세요.

이것을 건너뛰었다는 신호: 기능이 기존 if/else 체인을 분기 하나만큼 더 키우거나, 첫 번째와 동기화되어야 하는 두 번째 불리언이 생깁니다.
