# Boundary Discipline (경계 규율)

데이터가 시스템 경계(CLI 인수, 설정 파일, 외부 API, 네트워크)를 넘는 곳에서 검증하고, 타입을 좁히고, 에러를 처리하세요. 내부에서는 타입을 신뢰하세요. 재검증도, 중복 nil 체크도 하지 않습니다. 경계에서 원시 데이터를 도메인 타입으로 파싱하고, 전송 및 프레임워크 타입은 공개 표면 밖에 두세요. 비즈니스 로직은 프레임워크 의존성이 없는 순수 함수에 둡니다. 그것을 호출하는 껍데기는 얇게 유지하세요.

테스트는 두 가지입니다. 이 데이터가 지금 경계를 넘고 있는가? 그렇지 않다면 검증은 중복입니다. 껍데기가 그냥 호출하는 순수 함수가 될 수 있는가? 그렇다면 추출하세요.
