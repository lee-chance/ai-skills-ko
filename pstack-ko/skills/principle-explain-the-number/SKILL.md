# Explain the Number (숫자 설명)

- **실행하기 전에 결정을 작성하세요.** 결정을 바꿀 결과와 노이즈 플로어를 명명하세요. 실행 간 스프레드가 효과보다 클 때 멈추세요.
- **"왜 두 배가 아닌가?"라고 질문하세요.** 결과를 제한하는 리소스 또는 코드 경로를, 실행 중에 취한 프로파일이나 카운터에서 찾아 명명하세요. 코드를 읽고 추측한 것은 제한 요소가 아닙니다.
- **숫자가 측정하고 있을 수 있는 다른 것을 나열하고**(에러, 건너뛰거나 캐시된 작업, 실행되지 않은 코드, 튜닝되지 않은 쪽, 노이즈, 영향이 없을 만큼 작은 조각) 증거로 각각을 배제하세요.
- **실행 횟수, 스프레드, 제한 요소를 숫자와 함께 보관하세요.**

성능 숫자라면 [benchmark-checklist](../benchmark-checklist/SKILL.md) 스킬을 실행하세요. eval 결과라면 모든 실행이 작업을 수행했는지, 간격이 시도와 모델에 걸쳐 유지되는지, 시나리오가 중요한지 질문하세요.
