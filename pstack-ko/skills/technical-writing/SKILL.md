# Technical writing

피곤한 엔지니어가 첫 읽기에 이해할 수 있도록 작성하세요.

- 작업을 하지 않는 모든 단어를 자르세요.
- 짧고 일상적인 단어를 사용하세요: "utilize"가 아니라 "use".
- 규칙이 문장을 더 나쁘게 만들 때는 문장을 다른 방식으로 수정하거나 그대로 두세요.
- 동의어나 설명이 아니라 실제 심볼, 파일, 플래그 또는 명령 이름을 작성하세요.
- 전문 용어를 발명하지 마세요. 개발자가 소리 내어 말할 단어를 사용하세요. 명명된 패턴은 처음 나올 때 무엇을 의미하는지 말하세요.

## 리듬을 다양화하세요

- 문장 길이를 섞으세요. 두 가지 생각을 전달하는 문장은 분할하세요. 하나를 전달하는 긴 문장은 유지하세요.
- 설명에서는 시각을 가지세요. 참조는 건조하게 유지하세요.
- 구체적으로 쓰세요. "schema changes can cause issues"가 아니라 "a column rename fails the build".

## 먼저 모드 선택 (Diátaxis)

하나의 문서, 하나의 모드. 모드를 혼합하지 마세요. 대신 분할하고 링크하세요.

- **Tutorial: doing으로 학습.** 학습자가 빌드할 것을 말하세요. 모든 단계는 보이는 결과를 생성하고, 그들이 무엇을 봐야 하는지 말하세요. 설명은 한 절과 링크만 허용됩니다.
- **How-to: 목표로 가는 단계.** 독자의 문제를 해결하세요. 역량을 가정하세요. 행동만 담으세요. 포크를 허용하세요. 가이드를 작업으로 명명하세요.
- **Reference: 조회를 위한 사실.** 설명만 하세요. 건조하고, 완전하고, 확실하게. 설명된 것의 구조를 미러링하세요.
- **Explanation: 이해와 왜.** 하나의 경계가 있는 주제. 컨텍스트를 제공하세요: 설계 결정, 역사, 제약 조건, 대안. 의견은 여기서만 허용되고 다른 곳에서는 허용되지 않습니다.

## 독자에게 문장 작성 (Google 개발자 스타일)

- 독자에게 "you"로, 현재 시제로 말하세요.
- 누가 무엇을 하는지 말하세요. 액터가 알려지지 않았거나 요점 옆일 때만 수동형이 괜찮습니다.
- 지침을 명령으로 작성하세요. 지침 전에 조건을 두고, 일반적인 경우를 먼저 두세요.
- 유행어 없음, 비유적 언어 없음, "please" 없음, 절차에서 절대 "simply", "easy" 또는 "quickly" 없음.
- 사전 발표하지 말고, 동일한 구문으로 연속 문장을 시작하지 마세요.
- 링크가 어디로 가는지 말하는 단어로 링크하세요.
- 헤딩은 문장 케이스로 포인트를 전달합니다. 페이지당 하나의 h1, 건너뛴 수준 없음.
- 시퀀스에는 번호 목록, 다른 모든 것에는 글머리 기호. 완전한 문장으로 목록을 소개하세요. 항목을 병렬로 유지하세요.
- 코드는 코드 폰트로 갑니다. UI 요소는 굵게 표시됩니다. 직렬 쉼표를 사용하세요. "etc."를 삭제하세요.

## 진술이 한 번에 하나씩 로드되도록 만들기 (STE 규칙)

- 문장당 하나의 지침. 다른 모든 곳에서 문장당 하나의 생각.
- 약 20단어보다 긴 지침과 약 25단어보다 긴 다른 문장을 분할하세요.
- 보호하는 단계 전에 경고 또는 조건을 두세요.
- "the"와 "a"를 유지하세요.
- 각 단어에 하나의 의미를 주고, 액션당 하나의 단어를 선택하세요.
- 절대 내레이션으로 그리고 절대 수동형으로가 아니라 직접 명령으로 절차를 작성하세요.
- 가능한 곳에서 "-ing" 단어를 피하세요.

## 두 가지 읽기에 열려 있는 문장을 남기지 마세요 (Global English)

- "only"와 "not"과 같은 단어를 변경하는 단어 옆에 유지하세요.
- 긴 명사 문자열을 분해하세요.
- 모든 "it", "they", "this"가 하나의 명백한 것을 가리키게 만드세요. "this" 또는 "which"를 절대 전체 절을 가리키도록 사용하지 마세요.
- 동사나 "that"과 같이 구조를 보여주는 작은 단어를 삭제하지 마세요.
- 오독을 막을 수 있을 때는 나열에서 관사를 반복하세요. "and" 또는 "or"가 어떤 부분을 결합하는지 말하세요.
- 세미콜론이나 em 대시가 아니라 마침표를 사용하세요. 슬래시 없음, "(s)" 없음. 괄호 안의 텍스트를 완전한 문법 단위로 만드세요.
- 각 것을 어디서나 하나의 이름으로 호출하세요.
- 관용구, 구어, 라틴 약어 및 은유를 건너뛰세요.

## 목소리 및 저장소 특성

- 이 스킬이 터치하는 모든 문서에 **unslop** 스킬을 적용하세요. 해당 스킬은 slop 패턴 카탈로그를 소유합니다: AI 어휘, 필러, 헤징, 포맷 징후.
- PR 설명과 커밋 메시지도 쓰기입니다. Diátaxis를 제외한 모든 레이어가 그것들에 적용됩니다. PR 본문은 리뷰어가 1분 미만에 읽을 수 있는 브리핑입니다. swarm 로그, SHA 목록 또는 메트릭 테이블을 붙여넣지 마세요. 링크하세요.
- 제품 UI 문자열은 문서가 아닙니다. 그것들에 대해 제품의 복사 가이드라인을 사용하세요.
- 탭으로 코드 스니펫을 들여쓰세요. 실제 경로를 작성하세요. 모든 카운트 또는 트리 주장을 착륙시키는 커밋에서 참으로 만들고, 재생성하는 명령을 포함하세요.
