# 기여하기

모든 이슈는 [`SCOPE.md`](./SCOPE.md)의 기준에 따라 판단됩니다. 먼저 읽어보세요.

## 각 요청이 가는 곳

| 내용 | 이동 위치 |
| --- | --- |
| 스킬의 버그 | [Bug issue](https://github.com/mattpocock/skills/issues/new?template=bug.yml) |
| 기존 스킬에 대한 변경 | [Idea or feedback issue](https://github.com/mattpocock/skills/issues/new?template=idea.yml) |
| 질문, 또는 "어떻게 하나요...?" | [Discussions: Q&A](https://github.com/mattpocock/skills/discussions/categories/q-a) |
| 새 스킬 아이디어, 또는 기증할 스킬 | [Discussions: Ideas](https://github.com/mattpocock/skills/discussions/categories/ideas) |
| 다른 하네스나 이슈 트래커 지원 | [Discussions: Ideas](https://github.com/mattpocock/skills/discussions/categories/ideas), [`.out-of-scope/`](./.out-of-scope)를 읽은 후 |

풀 리퀘스트는 협력자에게만 열려 있으므로, 대신 이슈에 수정 사항을 설명하세요.

## AI로 작성된 이슈

에이전트가 도움을 주는 것은 환영하지만, 이슈를 게시하는 것은 여러분이므로, 여러분이 소유합니다:

- **이슈당 하나의 문제.** 한 세션의 여러 발견사항은 여러 이슈이거나, 아무것도 아닙니다.
- **짧게.** 한 화면에 맞지 않으면 줄이세요.
- **재현 먼저.** 문제를 보여주는 단계가 분석보다 먼저 옵니다.
- **스펙 붙여넣기 금지.** 전체 제안, 계획, 또는 다시 작성된 `SKILL.md` 파일이 없어야 합니다. 문제를 설명하세요. 수정은 우리가 설계합니다.
- **여러분 프로젝트의 이슈가 아닙니다.** 에이전트가 여러분 프로젝트의 스펙이나 티켓을 여기에 제출하면, 잘못된 저장소입니다. 프로젝트에서 `/setup-matt-pocock-skills`를 실행하세요.
