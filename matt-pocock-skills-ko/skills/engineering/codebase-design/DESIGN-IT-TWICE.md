# Design It Twice

선택된 deepening 후보에 대한 대안 인터페이스를 탐색하고 싶을 때 이 병렬 서브에이전트 패턴을 사용하세요. "Design It Twice"(Ousterhout)에 기반: 첫 번째 아이디어가 최선일 가능성은 낮습니다.

[SKILL.md](SKILL.md)의 어휘를 사용합니다: **모듈**, **인터페이스**, **심**, **어댑터**, **레버리지**.

## 프로세스

### 1. 문제 공간을 프레임화

서브에이전트를 생성하기 전에, 선택된 후보에 대한 문제 공간의 사용자 대면 설명을 작성하세요:

- 새 인터페이스가 만족해야 하는 제약 조건
- 의존할 의존성과 그것들이 속하는 카테고리([DEEPENING.md](DEEPENING.md) 참조)
- 제약 조건을 구체화하는 대략적인 예시 코드 스케치, 제안이 아니라 제약 조건을 구체적으로 만드는 방법

이것을 사용자에게 보여준 다음, 즉시 2단계로 진행하세요. 서브에이전트가 병렬로 작업하는 동안 사용자가 읽고 생각합니다.

### 2. 서브에이전트 생성

병렬로 3개 이상의 서브에이전트를 생성하세요. 각각 새로운 컨텍스트 윈도우를 가집니다. 각각은 깊어진 모듈에 대해 **급진적으로 다른** 인터페이스를 생성해야 합니다.

각 서브에이전트에 별도의 기술 브리프를 프롬프트하세요(파일 경로, 결합 세부 사항, [DEEPENING.md](DEEPENING.md)의 의존성 카테고리, 심 뒤에 무엇이 있는지). 브리프는 1단계의 사용자 대면 문제 공간 설명과 독립적입니다. 각 에이전트에 다른 설계 제약을 제공하세요:

- 에이전트 1: "인터페이스 최소화: 최대 1~3개의 진입점을 목표로 하세요. 진입점당 레버리지를 최대화하세요."
- 에이전트 2: "유연성 최대화: 많은 사용 사례와 확장을 지원하세요."
- 에이전트 3: "가장 일반적인 호출자에 최적화: 기본 사례를 자명하게 만드세요."
- 에이전트 4 (해당하는 경우): "심을 가로지르는 의존성에 대해 ports & adapters를 중심으로 설계하세요."

브리프에 [SKILL.md](SKILL.md) 어휘와 GLOSSARY.md 어휘를 모두 포함하여 각 서브에이전트가 아키텍처 언어와 프로젝트의 도메인 언어로 일관되게 명명하도록 하세요.

각 서브에이전트는 다음을 출력합니다:

1. 인터페이스 (타입, 메서드, 매개변수, 그리고 불변량, 순서, 오류 모드)
2. 호출자가 어떻게 사용하는지 보여주는 사용 예제
3. 구현이 심 뒤에 무엇을 숨기는지
4. 의존성 전략과 어댑터 ([DEEPENING.md](DEEPENING.md) 참조)
5. 트레이드오프: 레버리지가 높은 곳, 낮은 곳

### 3. 제시 및 비교

사용자가 각각을 흡수할 수 있도록 설계를 순차적으로 제시한 다음, 산문으로 비교하세요. **깊이**(인터페이스의 레버리지), **지역성**(변경이 집중되는 곳), **심 배치**로 대조하세요.

비교 후, 자신의 권장사항을 제공하세요: 어떤 설계가 가장 강력하다고 생각하는지와 이유. 다른 설계의 요소가 잘 결합된다면, 하이브리드를 제안하세요. 의견을 가지세요: 사용자는 메뉴가 아니라 강력한 읽기를 원합니다.
