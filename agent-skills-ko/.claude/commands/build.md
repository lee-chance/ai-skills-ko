## 모드

- **`/build`**: 대기 중인 *다음* 작업을 구현한 뒤 멈춥니다. 신중하게, 한 조각씩 진행합니다.
- **`/build auto`**: 필요하면 계획을 생성하고, 승인을 한 번 받은 뒤, 작업 사이에서 멈추지 않고 *모든* 작업을 구현합니다.

`$ARGUMENTS`가 모드를 고릅니다. `auto`(표준) 또는 `all`은 자율 모드입니다. 그 외의 값이나 빈 값은 기본인 단일 작업 모드입니다. 참고: 자율 모드는 작업당 더 빠르지 않습니다. 같은 테스트 주도 루프를 실행하며, 작업 사이의 사람 개입만 없앱니다.

## 기본: 작업 하나

계획에서 다음 대기 작업을 고르세요. 그다음:

1. 해당 작업의 인수 기준을 읽으세요
2. 관련 맥락(기존 코드, 패턴, 타입)을 불러오세요
3. 기대 동작에 대해 실패하는 테스트를 작성하세요 (RED)
4. 테스트를 통과하는 최소한의 코드를 구현하세요 (GREEN)
5. 전체 테스트 스위트를 실행해 회귀를 확인하세요
6. 빌드를 실행해 컴파일을 검증하세요
7. 설명이 담긴 메시지로 커밋하세요
8. 작업을 완료로 표시하고 멈추세요

## 자율: 계획 전체 (`/build auto`)

스펙이 있고 계획과 빌드를 한 번의 실행으로 묶고 싶을 때 사용하세요. 작업 사이의 수동 단계를 없앱니다. 검증은 그대로 둡니다. 모든 작업은 여전히 통과하는 테스트와 자기 커밋을 갖습니다.

1. **스펙을 요구하세요.** 알려진 경로의 스펙만 찾으세요. 저장소 루트의 `SPEC.md`, `docs/SPEC.md`, 또는 `spec/` 아래 파일입니다. README나 임의의 문서는 스펙으로 치지 않습니다. 없으면 멈추고, 사용자에게 먼저 `/spec`을 실행하라고 알려 주세요. 요구사항을 지어내지 마세요.
2. **깨끗한 기준선을 잡으세요.** `git status --porcelain`을 실행하세요. 예상되는 계획 아티팩트(`SPEC.md`, `docs/SPEC.md`, `spec/*`, `tasks/plan.md`, `tasks/todo.md`) 밖에 커밋되지 않은 변경이 있으면 멈추고, 사용자에게 커밋하거나, stash하거나, 처리 방법을 확인해 달라고 하세요. 작업별 자율 커밋이 관련 없는 로컬 작업을 흡수하면 깨끗한 롤백 보장이 깨집니다.
3. **필요하면 계획을 세우세요.** `tasks/plan.md`가 없으면 agent-skills:planning-and-task-breakdown을 호출해 계획을 생성하세요.
4. **단일 체크포인트.** 전체 계획을 제시하고, 모호하지 않은 긍정을 기다리세요 (예: "approve", "go", "yes"). 유보된 응답("looks reasonable", "I guess")은 승인으로 보지 마세요. 이것이 유일한 사람 게이트입니다. 승인 뒤에는 자율적으로 실행하세요. `tasks/plan.md`를 만들었다면, 지금 준비 커밋 하나로 커밋해서 첫 작업의 커밋에 섞이지 않게 하세요.
5. **의존 순서대로 모든 작업을 실행하세요.** 각 작업에 선언된 의존성을 쓰세요. 명시되어 있지 않으면 계획에 적힌 순서대로 실행하세요. 각 작업마다 위의 기본 루프 전체를 돌리세요 (RED → GREEN → 회귀 → 빌드 → 커밋 → 완료 표시). 그 작업이 건드린 파일과 작업 상태 업데이트만 스테이징하세요. `git add -A`를 맹목적으로 쓰지 마세요. 작업당 커밋을 하나씩 만들어, 어느 지점에서든 깨끗하게 롤백할 수 있게 하세요.
6. 다음 경우에는 **멈추고 사용자에게 물어보세요**. 그대로 밀어붙이지 마세요.
   - 테스트를 통과시킬 수 없거나, 명백한 수정 없이 빌드가 깨질 때. agent-skills:debugging-and-error-recovery를 따르세요
   - 스펙이 모호하거나, 작업에 스펙이 다루지 않는 결정이 필요할 때
   - 작업이 고위험이거나 되돌릴 수 없을 때. 인증/권한 변경, 파괴적인 데이터 마이그레이션, 결제, 삭제, 배포, 시크릿을 건드리는 모든 것, **또는 `git revert`로 되돌릴 수 없는 모든 것**. agent-skills:doubt-driven-development를 따르고, 계속하기 전에 명시적 승인을 받으세요

   사용자가 막힌 지점을 해결한 뒤 `/build auto`를 다시 호출하면, 다음 대기 작업부터 이어집니다.
7. **마지막에 요약하세요.** 완료한 작업, 추가한 테스트, 만든 커밋, 그리고 건너뛰거나 표시하거나 사용자에게 남긴 항목을 적으세요.

어느 단계든 실패하면 agent-skills:debugging-and-error-recovery 스킬을 따르세요.
