사용자가 무엇을 만들려는지 파악하는 것부터 시작하세요. 다음에 대해 확인 질문을 하세요.
1. 목표와 대상 사용자
2. 핵심 기능과 인수 기준
3. 기술 스택 선호와 제약 조건
4. 알려진 경계 (항상 할 일, 먼저 물어볼 일, 절대 하지 않을 일)

그다음 여섯 핵심 영역을 모두 담은 구조화된 스펙을 생성하세요. 목표, 명령, 프로젝트 구조, 코드 스타일, 테스트 전략, 경계입니다.

요청이 독립적으로 테스트 가능한 여러 역량을 하나로 묶고 있으면, 먼저 스킬의 Phase 0에 따라 역량 맵(모듈 id, 의존 방향, 빌드 순서)을 제안하고 승인을 받으세요. 그다음 의존 순서대로 각 모듈의 스펙을 작성하세요.

스펙을 프로젝트 루트의 SPEC.md로 저장하고, 진행하기 전에 사용자에게 확인받으세요.
