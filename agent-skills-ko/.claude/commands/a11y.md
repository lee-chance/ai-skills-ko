agent-skills:accessibility-engineering 스킬을 호출하세요.

`/a11y`는 전용 접근성 감사를 실행합니다. 키보드 탐색, 스크린 리더 지원, 색상 대비, 폼 레이블, 구조적 WCAG 2.2 AA 준수를 점검합니다.

## 모드 결정

**심층 모드 (Deep)**: 다음 중 하나라도 있으면 활성화하세요.
- axe-core 또는 pa11y JSON 보고서 파일 (`bash skills/accessibility-engineering/scripts/audit-a11y.sh url <url> --json`으로 실행)
- 라이브 URL. 에이전트가 사용자에게 위의 감사 스크립트를 실행하라고 안내할 수 있습니다
- Chrome DevTools MCP (라이브 DOM 검사, 대비 확인, 렌더링 분석용)

**빠른 모드 (Quick)**: 사용할 수 있는 도구 출력이 없을 때의 기본입니다. 소스 코드에서 구조적 안티패턴(레이블 누락, div를 버튼으로 사용, alt 텍스트 없음, 제목 수준 건너뜀)을 찾습니다.

## 감사 실행

`accessibility-auditor` 서브에이전트를 생성하세요. 다음을 명시적으로 넘기세요.

- 리뷰 대상 파일, 컴포넌트, 또는 diff
- 아티팩트 경로 (axe-core JSON, pa11y JSON, 감사 스크립트 출력)
- 알 수 있을 때의 대상 URL 또는 컴포넌트
- 기대하는 모드 (Quick 또는 Deep). Deep를 의도했다면, 빠진 입력을 에이전트가 드러내게 하세요

서브에이전트는 WCAG 스코어카드, 심각도별로 순위가 매겨진 발견 목록, 긍정적인 관찰, 코드 예시가 있는 수정 안내를 반환합니다.

## 출력

전체 감사 보고서를 사용자에게 반환하세요. 종합이나 병합 단계는 필요 없습니다. 이 명령은 페르소나 하나입니다.
