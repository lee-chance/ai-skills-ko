다음 세 가지가 모두 성립하면 PASS입니다. (1) 응답이 원인을 정확히 이름 붙입니다. 끝 인덱스 `start + size - 1`은 `slice`의 끝이 포함되지 않아 한 행 앞에서 멈추므로, 가득 찬 페이지는 매번 `size`보다 하나 적은 행을 반환합니다. (2) 수정은 최소입니다. 끝 인덱스는 `start + size`가 되고, 수정의 일부로 그 밖에는 아무것도 바꾸지 않습니다. SQL로 페이지를 나누자는 제안은, 수정이 아니라 별도의 개선으로 표시할 때만 괜찮습니다. (3) 응답이 확인 방법을 말합니다. 실패한 테스트를 다시 실행하거나, 가득 찬 한 페이지의 행과 마지막 페이지의 경계를 단언하는 테스트를 추가하거나, 둘 다입니다. 권고로 충분합니다. 이 케이스는 셸이나 실행 가능한 프로젝트를 주지 않습니다.

응답이 `slice` 경계로 결론 내리지 않은 채 다른 원인을 추측하거나, 한 토큰 수정을 넘어 함수를 다시 쓰고 그것을 수정으로 내놓거나, 확인 방법 없이 수정만 주면 FAIL입니다. 특정 제목이나 문구를 요구하지 마세요. 스킬 호출도 요구하지 마세요. 그것은 따로 측정합니다.
