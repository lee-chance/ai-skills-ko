# 완료 정의

모든 변경이 완료로 인정받기 전에 넘어야 하는, 프로젝트 전체에 상시로 두는 기준입니다. 인수 기준은 작업마다 달라지며 "올바른 것을 만들었는가?"에 답합니다. 완료 정의는 매번 같고 "우리 기준대로 끝났는가?"에 답합니다. `planning-and-task-breakdown`, `incremental-implementation`, `shipping-and-launch`의 마지막 관문으로 사용하세요.

## 완료 정의와 인수 기준

| | 인수 기준 | 완료 정의 |
|---|---|---|
| 범위 | 하나의 작업이나 스펙에 한정 | 모든 증분에 적용 |
| 변동 | 항목마다 다름 | 고정되어 재사용 |
| 답하는 질문 | "우리가 *이것*을 만들었는가?" | "*준비*되었는가?" |
| 담당 | 작업을 계획할 때 정의 | 프로젝트에 대해 한 번 정의 |
| 예시 | "사용자가 이메일 링크로 비밀번호를 재설정할 수 있다" | "테스트가 통과하고, 회귀가 없으며, 문서가 갱신되었다" |

둘은 서로 보완합니다. 작업은 **그 작업의** 인수 기준을 충족하고, 상시 완료 정의도 만족할 때만 완료입니다. 어느 한쪽을 빠뜨리면 끝난 것처럼 보이는 일이 남습니다.

## 상시 체크리스트

완료라고 선언하기 전에 모든 변경에 이 목록을 적용하세요.

### 정확성
- [ ] 해당 작업의 인수 기준을 모두 충족합니다
- [ ] 코드가 의도대로 실행되고 동작합니다. 컴파일이나 타입 체크만이 아니라 런타임에서 확인합니다
- [ ] 새 동작을 테스트가 다룹니다. 변경이 없으면 실패하고, 변경이 있으면 통과합니다
- [ ] 기존 테스트가 계속 통과합니다. 회귀가 들어오지 않았습니다
- [ ] 정상 경로, 엣지 케이스, 오류 경로를 모두 처리합니다

### 품질
- [ ] 코드가 이름과 구조로 의도를 드러냅니다. *무엇을* 하는지 설명하는 주석이 필요 없습니다
- [ ] 비즈니스 로직이 중복되지 않습니다
- [ ] 죽은 코드, 디버그 출력, 주석 처리된 블록이 남아 있지 않습니다
- [ ] 변경은 해당 작업 범위 안에 있습니다. 무관한 리팩터가 섞여 있지 않습니다
- [ ] 린트와 포맷팅이 통과합니다

이 항목을 더 깊게 다루는 곳은 `code-review-and-quality`(5축 리뷰)와 `code-simplification`(동작은 그대로 두고 복잡도를 줄이기)입니다.

### 통합
- [ ] 변경이 나머지 시스템과 함께 동작합니다
- [ ] 데이터베이스 마이그레이션, 설정 변경, 피처 플래그를 반영했습니다
- [ ] 공개 인터페이스나 API를 바꾸는 경우 하위 호환을 고려했습니다

### 문서
- [ ] 공개 인터페이스, API, 사용자에게 보이는 동작을 문서화했습니다
- [ ] 남겨 둘 가치가 있는 아키텍처 결정을 기록했습니다(`documentation-and-adrs` 참고)
- [ ] 문서는 변경 이력을 늘어놓지 않고, 현재 상태를 시점과 무관한 언어로 설명합니다

### 출시 준비
- [ ] 신뢰할 수 없는 입력, 인증, 데이터 처리에 대한 보안 영향을 리뷰했습니다(`security-and-hardening` 참고)
- [ ] 새 핵심 경로에 옵저버빌리티가 있습니다(로그, 메트릭, 트레이스)(`observability-and-instrumentation` 참고)
- [ ] 위험한 변경에는 롤백 경로가 있습니다(`shipping-and-launch` 참고)
- [ ] 머지하거나 배포하기 전에 사람이 리뷰하고 승인했습니다

## 적용 방법

- **작업마다**: 작업을 완료로 표시하기 전에 정확성과 품질 절을 확인하세요.
- **기능마다**: 기능을 완료로 보기 전에 통합과 문서 절을 확인하세요.
- **릴리스마다**: 전체 체크리스트가 하한입니다. `shipping-and-launch`가 그 위에 배포용 관문을 더합니다.

목록은 프로젝트에 맞춰 한 번만 다듬고, 그다음부터는 그대로 재사용하세요. 스프린트마다 다시 협상하는 기준은 완료 정의가 아닙니다.

## 레드 플래그

- "다 됐다, 아직 실행만 안 해 봤다": 검증하지 않은 작업은 완료가 아닙니다.
- 문서, 회귀, 런타임 검증을 건너뛴 채 "테스트가 통과한다"를 완료와 같은 말로 씁니다.
- 마감 압박에 따라 기준이 달라집니다.
- 인수 기준만 전체 기준으로 삼고, 상시 품질 하한이 없습니다.
- 사람의 리뷰가 필요한 변경인데, 리뷰 전에 "완료"를 선언합니다.
