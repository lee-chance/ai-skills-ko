# 리허설

드레스 리허설입니다. 누구보다 먼저, 데모 전체를 실제 속도로 실행하고 관객이 볼 방식으로 보세요. 만든 모든 이미지를 읽고, 촬영한 페이지가 작성한 코드를 실행하는지 확인하세요. 필름 줄이 강제하는 규칙은 `framing.md`, `craft.md`, `motion.md`에 있습니다. 이 파일은 촬영 방법과 볼 것입니다.

## 안무 전에 스틸을 증명하세요

보여 주는 크기에서 골드 옆에, 출고하는 두 너비로 열림과 보상을 렌더하세요. 모션 감소 포스터는 열림이 아니고, 유일한 프레임으로 작동해야 합니다 (`motion.md`, 스토리). `verify.md`의 스틸 질문(프레이밍, 계층과 밀도)을 물은 다음:

- 보는 사람이 브랜딩이나 카피보다 먼저 초점 객체와 바뀌는 것을 찾을 수 있는가?
- 브리프의 모든 객체가 있는지와 따로, 품질(계층, 밀도, 간격, 크롭, 재질)을 골드와 비교하세요.
- 가장 바쁜 중간 스토리 프레임과 바뀐 모든 휴식 상태에도 같게 하세요. 깨끗한 도구 보고는 구성 질문을 닫지 않습니다.

## 호스트 자신의 컨트롤

데모는 선택기, 재생 버튼, 레이블이 있는 페이지에 살고, 그것들도 판단받습니다. `scripts/layout.mjs`는 Stage 밖의 보통 UI를 검사하며, 벤토 타일의 안쪽 크롭(`nested-composition-crop`)도 포함합니다.

```sh
node scripts/layout.mjs "<url>/?example=hero-demo" --select .pg --width 390 --report shots/host-layout.json --screenshot shots/host-layout.png --strict
```

뷰어 페이지, 직접 장면 경로, 실제 목적지 페이지를 실제 너비에서 실행하세요. 움직이는 지오메트리는 통과가 아니라 미완료로 보고됩니다. 각 컨트롤을 휴식, 호버 인·아웃, 눌림, 포커스, 바뀐 레이블, 전환 중 중단에서 보세요. 지오메트리는 텍스트 렌더링, 포커스 스타일, 필터된 실루엣을 보증하지 않습니다.

## 촬영

`scripts/film.mjs`는 헤드리스 Chrome에서 페이지를 열고 고정 간격으로 스테이지를 실제 크기의 콘택트 시트 하나로 찍습니다. 콘솔과 `[stageshow]` 경고(루프 이음새, 없는 타겟)를 인쇄합니다. `--help`가 모든 플래그를 나열합니다.

처음: `kit/` 옆에 `scripts/`를 복사하고, `npm i -D playwright-core`(CSS 검사에는 `postcss`)를 설치하세요. `CHROME_PATH`가 다른 Chrome을 고릅니다. 키트 자체는 둘 다 필요 없습니다.

플레이그라운드에서는 직접 `?capture=<name>` 경로를 촬영하세요(보통 뷰어는 장면을 iframe으로 감쌉니다). 사이트에서는 실제 페이지 URL입니다(필요할 때 임베드된 프레임의 URL을 직접 여세요). 뷰어의 재생, 일시정지, 재개, Replay는 여전히 직접 보세요.

```sh
node scripts/film.mjs "<url>/?capture=hero-demo" --out shots/hero.png --every 1000 --count 18
node scripts/film.mjs <url> --out shots/still.png --still                        # one clean image of a still
node scripts/film.mjs <url> --out shots/phone.png --width 390 --every 2500 --count 6
node scripts/film.mjs <url> --out shots/drop.png --at drop --every 50 --count 24   # one beat, frame by frame
node scripts/film.mjs <url> --out shots/zoom.png --zoom 380,40,240,120 --still    # close-up, in stage design px
node scripts/film.mjs <url> --out shots/hover.png --hover --every 300             # play="hover": rest, hover, leave
node scripts/film.mjs <host-url> --select "#feature-demo" --report shots/report.json --strict
```

- **선택과 마크.** 필름은 보이는 모든 `.ss-stage`를 찾습니다(숨은 컴팩트나 와이드 쌍은 건너뜁니다). `--select`가 좁히고, `--at`과 `--zoom`은 스테이지 하나가 필요합니다. 비트에서 `act.mark('drop')`을 호출하고 `--at drop`으로 촬영하세요. 지연을 짐작하지 마세요.
- **클로즈업.** `--zoom x,y,w,h`는 고해상도의 스테이지 디자인 픽셀입니다. `--zoom target:<name>[,pad]`는 매 프레임 `data-target`을 따릅니다. 스틸은 굴러가는 `Count`가 착지할 때까지 기다립니다.
- **호버 스테이지.** `--hover`는 휴식, 호버, 떠난 뒤의 정착을 촬영합니다. 휴식 프레임은 스틸로 서 있어야 하고, 떠남은 점프 없이 미끄러져 돌아가야 합니다.
- **룩과 너비.** `--dark`는 다크 테마를 촬영합니다. 550 열에는 `--width 566`. `--slow 6 --every 40`은 착지나 누르기를 가깝게 샘플합니다(스테이지와 CSS가 둘 다 느려집니다).
- **점프.** 필름은 애니메이션 프레임마다 지오메트리를 기록하고 타임스탬프의 `jump:`와 `drift:` 후보를 보고합니다. 우연한 것을 고치세요. 의도적인 단계는 `data-snap`으로 좁게 표시하세요. `node scripts/jumps.mjs "<url>/?capture=<name>" --ms 30000 --report shots/jumps.json`은 스크린샷 오버헤드 없이 더 긴 스캔을 실행합니다.
- **커버리지.** 비었거나, 짧거나, 간격이 있는 녹화(일반적인 간격의 1.6배를 넘는 간격, 40ms를 넘는 간격)는 `inconclusive`, 종료 코드 2입니다. 카메라 누락과 같은 상자의 텍스트 변화는 수동 리뷰용으로 나열됩니다.
- **보고.** `--report <path>`는 JSON을 씁니다(`status`와 `exitCode`, 각 스테이지의 `coverage`, `findings`, `manual`은 `stages` 아래). `--strict`는 후보에서 1로 종료합니다. `no-issues-detected`는 승인이 아닙니다. 지속되는 개발 리로드에서는 종료 코드 3입니다.
- **클래스 충돌.** `node scripts/class-clash.mjs <demo folders>`(postcss 필요)는 겹치는 클래스 네임스페이스를 검사합니다. 범위가 있는 `.row`는 괜찮고, 범위가 없는 것은 아닙니다. 복잡한 루트는 미결입니다. 반복되는 데모도 호스트에서 함께 확인하세요.

## 절대 의도적이지 않은 줄

판단의 후보가 아닙니다. 원인을 고치고 다시 촬영하세요. `film.mjs --gate`는 모두 0일 때만 `rehearsal passed`로 끝납니다. 가리키는 것을 숨기거나, 제거하거나, 표시해서(`data-crop`, `data-snap`) 줄을 지우는 것은 버그이며, 새로운 눈이 의도적이라고 부르는 모든 줄을 다시 판단합니다.

| 줄 | 의미 |
|---|---|
| `framing:` | `framing.md`가 금지하는 거터, 블리드, 크롭, 창 형태. 온전히 떠 있는 히어로. 가장자리에 붙은 팝오버 |
| `cut by the crop:` | 스테이지 가장자리에 잘린 액션이나 칩. 필러는 블리드하고, 액션은 온전히 읽히거나 전혀 읽히지 않습니다 |
| `tight stack:` / `loose stack:` | 부제 위의 제목, 잉크 사이 3px 미만, 또는 작은 레이블에서 10px을 넘어 떠 있음(4~6px이 맞음) |
| `tight mark:` | 아바타나 텍스트에서 5px 안의 상태 점, 또는 행 밖(6px 떨어짐) |
| `tight inset:` | 창, 카드, 행 가장자리에서 8px 미만의 단어(12px이 맞음) |
| `skeleton ladder:` | 사실적 충실도에서, 프레임 안의 목록(4행 이상)에서 단어 없는 행(최소 3)이 단어 있는 행보다 많음 |
| `onion skin:` | 휴식에서 겹치는 비쳐 보이는 채움 |
| `kit override:` | 키트 부분의 지오메트리(행, 버블, 스탬프, 아바타, 휴대폰)를 다시 빚는 CSS |
| `unit wrapped:` | 자체 줄의 통계 단위 |
| `unsized text:` | 크기를 정한 것이 없어 스테이지의 16px 기준선에 남은 창 안의 텍스트 |
| `clipped glyph:` | 상자를 넘어 그려진 아이콘 |
| `loose list:` | 창을 채우려고 벌어진 행 |
| `fat row:` | 단어보다 세 배 큰 한 줄 행 |
| `empty pane:` | 창이나 화면 콘텐츠 아래의 공백 |
| `emoji icon:` | 아이콘 자리의 이모지 |
| `anchor drift:` | 목록 높이가 바뀌며 움직이는 열린 팝오버 |
| `uneven padding:` | 콘텐츠가 측면 인셋보다 한 가장자리에 약 1/3 더 가깝거나, 그것을 넘는 카드나 타일 |
| `mixed icons:` | 한 내비게이션, 목록, 툴바에서 나란한 채움 글리프와 윤곽 글리프 |
| `tight control:` | 위의 필드, 선, 카드 가장자리와 사이가 8px 미만인 버튼이나 칩 |
| `invented mark:` | 실제 회사 이름 옆의 브랜드 색 한 글자 타일 |
| `uneven inset:` | 자식이 한 끝에 훨씬 더 가까운 바, 알약, 컨트롤 행 |
| `uneven gutters:` | 타일에서 한쪽에 훨씬 더 가까운 창이나 패널 |
| `avatar alignment:` | 이름의 가장자리가 아니라 아바타 아래에서 시작하는, 아바타 행 아래의 본문 |
| `spills its slot:` | 배치된 너비를 넘어가거나 행의 간격을 닫는 콘텐츠. 자체 레이어로 그려져 이웃 단어에 닿거나 카드를 넘는 링 |

`[stageshow] selection drift` 키트 경고(I-beam 아래에 있지 않은 텍스트 선택)도 게이트를 실패시킵니다.

## 다른 필름 줄

후보입니다. 각각 규칙 옆에 이름 있습니다. `craft.md`에서: `touching`(상자에서 5px 안의 텍스트)과 `tight lines`(대신하는 텍스트보다 가까운 바), `lopsided`, `uneven`, `near-tangent`, `half-pixel glyph`, `squeezed`. `motion.md`에서: `covers`, `dashed edge resizes`, `handoff shift`, `settle snap`, `fly size`, `hard edge`, `appears, then moves`, `near-empty frames`, `lands on a transform`, `steps in its box`. 여기서만 정의됩니다.

- `clipped:`는 스테이지 안의 컨테이너 가장자리에 잘린 마크입니다. 고치거나, 크롭이 의도적일 때만 컨테이너에 `data-crop`을 표시하세요.
- `unclipped:`는 페이지가 크롭을 결정한다는 뜻입니다. 스테이지에 `overflow: hidden`을 주세요. `double corner`는 반지름이 다른 둥근 클립 둘이 가장자리를 공유한다는 뜻입니다. 하나에 모서리를 주세요.
- `appears with no entrance`와 `vanishes with no exit`는 샘플링 간격에서 놓칠 수 있습니다. 각 나타남과 사라짐을 50ms에 촬영하세요. 즉각적인 타이핑 피드백은 의도적일 수 있습니다. 전체 필드나 하위 트리가 아니라 정확히 바뀌는 노드에 `data-typing`이나 `data-snap`입니다.
- `shrunk, not laid out for the phone: drawn at 0.72`는 그 너비에서 타입이 작게 읽힌다는 뜻입니다. `compact`를 주세요. `grown past the design size`는 크게 읽힌다는 뜻입니다. `small text: X renders at Npx`는 10px 미만 텍스트이며, 600 미만 너비에서 검사됩니다.
- 그리기를 의도적으로 이끄는 펜 끝은 `data-lead`를 답니다.

## 볼 것

- **프레이밍이 먼저입니다.** 스틸을 촬영하고 모션 작업 전에 모든 `framing:`과 `cut by the crop:` 줄을 지우세요. 무엇이든 옮긴 뒤에는 루프 전체를 다시 촬영하세요.
- **실제 너비의 모든 프레임,** 로드되기 전에 뷰에 있는 도형도 포함합니다.
- **눈대중하지 말고 측정하세요.** 페이지 전체의 계산된 스타일을 비교하세요(그림자, 플레이트, 반지름 세트 하나). 시트가 아니라 애니메이션 프레임마다 모프를 샘플하세요.
- **루프를 끝까지.** 전체 루프 하나와 다음의 시작을 촬영하세요. 모든 `loop seam` 경고를 조사하세요.
- **텍스트와 글리프.** 이동 뒤에 `--slow 4`로 픽셀을 살펴보세요. 합성 레이어는 가능한 수정이지, 픽셀이 가만히 있었다는 증명이 아닙니다. 어떤 프레임에서도 상자 밖으로 넘치지 않습니다.
- **드래그 전체,** 속도로 호버에서 정착까지, 그다음 단계별로. 표면은 누르기 전에 들리지 않습니다. 모든 변환을 통해 손의 핫스팟을 추적하세요. 그립 점의 임시 크기 0 자식이 브라우저가 모든 변환을 투영하게 합니다(부모 테두리를 빼세요). 손으로 쓴 행렬은 분리된 `translate`, `rotate`, `scale`을 놓칠 수 있습니다.
- **오버레이가 착지합니다.** 하이라이트, 선택, 마커는 모든 스케일에서 설명하는 것 위에 있습니다. 드래그 상자를 주장하는 항목과 대조하세요.
- **크롭이 스스로를 설명합니다.** 화면이 스테이지와 만나는 모든 가장자리는 페이드하거나, 의도를 가지고 블리드하거나, 실제 창 가장자리입니다.
- **가장자리와 모서리.** 호버 채움과 선택된 행을 확대하세요. 부모의 `overflow: hidden` 아래에서도 둥근 모서리가 온전합니다.
- **가장 좁은 출고 호스트.** 거터를 포함해 390과, 브리프가 이름 지으면 그 너비에서 루프 전체를 촬영하고, 와이드 패스만큼 자세히 읽으세요.
- **출고하는 모든 룩,** 따로 촬영합니다.
- **호스트를 확인하세요.** 데모가 모든 출고 너비의 실제 페이지에서 작동합니다(플레이트, 그라운드, 패딩, 크롭). 페이지 배경은 호스트에 남고, 컴포넌트는 전체 페이지 래퍼를 가져오지 않습니다.
- **모션 감소.** `--reduced`는 포스터를 보여 줍니다. 스틸이고 완전합니다. `rect()`의 오버레이가 그 안에 올바르게 있습니다. 재생 중 환경설정을 토글하고 되돌리세요. 연출 대기는 빼고, 작업 타이밍과 읽는 시간은 유지하세요.
- **라이브 페이스.** 가상 시계는 지오메트리를 증명하지 프레임 레이트는 증명하지 않습니다. 실제 페이지에서 변환에 대해 rAF 타임스탬프를 기록하세요. 반복되는 포즈 다음 점프는 시계 버그입니다. 일시정지, 화면 밖, 숨은 탭, 끝난 `once` 장면은 일을 멈춥니다. 재개와 다시 재생은 비트를 건너뛰거나 누적을 다시 재생하지 않습니다. 확인한 브라우저와 기기를 말하세요.
- **타입 검사.** 호스트의 타입 검사를 실행하세요(스킬 폴더에서 `npm run typecheck`). 관련 없는 실패는 따로 보고하고, 통과로 걸러내지 마세요.
- **청사진 그리드.** 선은 `--ss-grid-x`와 `--ss-grid-y`에 있습니다. Stage에 설정해서 창 가장자리가 그리드 선에 착지하게 하세요.
- **도구가 승인할 수 없는 것.** 콘택트 시트는 한 프레임 플래시를 놓칩니다. 스캔은 모프, 스토리, 제스처가 옳은지 모릅니다. 속도로 재생, 느린 전환, 루프와 다음 시작, 중단, 모션 감소, 화면 밖에서의 복귀를 보세요. 최종 편집 뒤에 다시 하세요. 플레이그라운드는 각 예시를 iframe에 격리합니다. Pause와 Step은 시계 하나를 진행합니다. Phone은 너비를 바꾸지만 터치는 바꾸지 않으므로, 기기나 입력 에뮬레이션으로 터치를 확인하세요.

그런 다음 시트를 가장 가까운 골드의 것 옆에 두세요. 이것이 즉시 실제 제품이고, 조용하며, 분명한 스토리 하나입니까? 예가 될 때까지 반복하세요.
